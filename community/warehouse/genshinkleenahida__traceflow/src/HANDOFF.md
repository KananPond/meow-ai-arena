# 循迹仓流（Traceflow）交接说明

## 目标与运行约束

本实现独立重写第一轮仓储调度仿真，以 `warehouse/workspace/baseline/` 的实际行为为标准。凡是能通过 `tools/check_input.py --full` 的输入，输出都应与基线逐字节一致；换行按评测规则处理。会影响输出的旧行为必须保留。

代码只使用 C++20 标准库。仿真程序只读标准输入、写标准输出，不访问文件、网络、其他进程，也不在两次运行之间保存缓存。所有地图、距离、路线和状态缓存均由本次输入建立。

在投稿目录按固定参数编译：

```sh
g++ -O2 -std=c++20 src/*.cpp
```

在仓库根目录执行社区检查：

```sh
python3 community/check.py community/warehouse/genshinkleenahida__traceflow --skip-eval
python3 community/check.py community/warehouse/genshinkleenahida__traceflow
python3 community/check.py community/warehouse/genshinkleenahida__traceflow --full
```

默认档包含 5 组公开负载和 3 组隐藏负载；`--full` 包含第一轮全部 8 组隐藏负载。两档的几何平均口径不同，不能混用。正式测试结果、CPU 时间和加速比以相应官方检查生成的自测摘要为准，本交接文档不固化性能数字。

## 固定阶段与共享状态

每个 tick 严格执行：

`events → rescue → charge → dispatch → seekChargers → move → report`

`report` 仅在 `(tick + 1) % reportEvery == 0` 时执行。相同 tick 的外部事件保持输入顺序。救援、找桩和移动保持机器人编号升序；前一个机器人更新的占据或充电预订立即对后面的机器人可见。

路网只包含永久墙和动态封锁，**机器人占据不属于路网**。占据只在执行移动、让路和救援等操作时检查，不能直接加入 BFS 图。

## 路径查询的五层结构

### 1. 永久墙图的完整距离

`staticTo(target)` 对忽略动态 BLOCK 的永久墙图运行一次完整 BFS，并按目标缓存。静态距离是任何动态地图中距离的下界；永久墙不变时，该距离表无需因 BLOCK/UNBLOCK 重算。

距离使用 `uint16_t`：`65534` 表示墙，`65535` 表示静态不可达。合法地图有实墙边框，最大 200×200，非墙格至多 198² 个，有限简单最短路最多 39,203 步，因此不会碰到这两个标记。

静态 BFS 先用哨兵表初始化距离，再用扁平队列访问上、右、下、左邻格。入队的非墙格都在边框内部，扁平邻居索引不会越界。队列的 `queue[tail] = neighbor` 可在未实际入队时写入尾部暂存位；实墙边框保证入队总数严格小于 `W×H`，所以该暂存位始终在已分配队列内。若以后取消边框约束，必须一起修改邻居访问和这个容量前提。

### 2. 动态地图中的最短路 DAG 可达证书

每张静态距离表同时保存一张布尔 `reachable` 表。它表示：当前仍存在一条完全开放的路径，沿静态距离每步减一走到目标。所有这样的边形成按距离分层的有向无环图。

- 证书为真时，已有可行路线达到静态下界，因此静态距离就是当前精确距离。
- 证书为假时，只能说明原来的静态最短距离无法达到；当前地图仍可能存在更长绕路。因此必须继续精确求解，不能直接判不可达。

只有实际改变通行性的 BLOCK/UNBLOCK 才增加 `version_` 并记入变化日志。重复操作、墙格和越界操作不改变版本。

证书在再次使用时追到当前版本：

- **BLOCK：**先删除本批最终仍封锁的顶点，再沿距离递增方向传播。一个顶点仅在所有距离减一的有效前驱都消失后才失效。
- **UNBLOCK：**若开放格是目标，或已有可达的距离减一前驱，便恢复它的证书，再沿距离递增方向传播。
- **较旧证书：**相差超过 64 次实际拓扑变化时，从静态有限距离重新建立证书，再应用当前全部封锁。这个阈值只选择工作方式，不改变结果。

`distance()` 在证书成立时直接返回下界。`nextStep()` 先求可行邻格的最小静态距离，再按上、右、下、左选择具有该距离且证书成立的第一个邻格；若不能证明，则进入下述有界局部绕行或动态精确距离回退。前面某个同下界邻格若证书为假，其实际距离必然更大或不可达，因此这个快捷选择保持基线的方向平手规则。

最近充电桩也有一张永久墙图上的多源静态距离及相同证书，静态根包含所有 `C`。被封桩不能维持根证书；证书失败时回到当前可通行桩的多源 BFS。

### 3. 每机器人的静态规范完整路线

`canonicalRoute()` 读取静态距离表，从当前格开始，每步选上、右、下、左中第一个静态距离减一的邻格。构造过程中不跳过被封的规范选择去寻找第二选择：只要整条规范路线中有后续格被封，就放弃此缓存并回到 `nextStep()`。

若整条路线当前开放，它既达到永久墙图距离下界，又在该图所有最短路中具有最小方向序列。因此它也是当前地图的基线规范路线。之后的 UNBLOCK 不可能生成比永久墙图规范路线更短或更早的路线；只有新 BLOCK 命中剩余路线才需要失效。

`Simulator::routeStep()` 为每个机器人保存路线、下一步游标、起点、目标及最后检查版本：

- 观察到机器人实际走到缓存的下一格后才推进游标；等待不会消费路径。
- 目标变化、sidestep 或其他位置错位会弃用旧路线。
- 地图变化时只检查变化日志中新 BLOCK 与剩余路线的交集；最终已重新开放的格不构成阻断。
- 每机器人使用 `uint16_t positions[N]` 加速成员判断。旧位置标记无需整表清空：同时验证位置在剩余范围内且 `route[position] == changedCell`，即可排除旧路线残留。
- 源格不放进路线，因此源被封后仍可正常离开。
- 构造失败按当前源、目标和地图版本记忆，避免原地等待时逐 tick 重试。

完整路线与静态距离缓存各自持有自己的数据，静态表被 LRU 淘汰不会使已经构造的路线悬空。只需要读永久墙距离时使用 `staticTo(target, false)`，避免修复随后并不需要的全域证书。

### 4. 用静态势函数搜索局部绕行

这一层只接在 `nextStep()` 的 DAG 快路之后；`distance()`、最近桩查询和完整规范路线保持各自原有处理。若目标已经有当前地图版本的动态精确距离场，直接复用该场，不额外做点搜索。

**重标权与精确距离。** 固定目标 `t`，令 `h(v) = d_static(v, t)`，即永久墙图中的精确距离。在目标所在静态连通分量内，任意相邻地面格 `u, v` 的距离差至多为 1；四邻单位格图又是二部图，相邻格的距离奇偶性不同，所以距离差恰为 `+1` 或 `-1`。因此可定义：

```text
w'(u,v) = (1 + h(v) - h(u)) / 2 ∈ {0,1}
```

对任意合法 `s -> t` 动态路径，势函数项相消；若其重标权总和为 `k`，则路径原长度为 `h(s) + 2*k`。最小化 `k` 等价于最小化真实路径长度。动态封锁只删除永久墙图中的顶点，不破坏这个等式；`k` 可理解为沿该路径向更大静态距离移动的步数。这是已有最短路势函数重标权在四邻单位格图中的特化，不是近似启发式。一般形式可参见 Eppstein 的 [Finding the k Shortest Paths](https://ics.uci.edu/~eppstein/pubs/Epp-SJC-98.pdf) §2.2、Lemma 1–2。

**把已认证的 DAG 当作终端集合。** 调用 `staticTo(target)` 时先将 `reachable` 追到当前版本。任意 `reachable[v] == true` 的格子都有一条完全开放、每步让 `h` 减一的后缀，因此从 `v` 到目标的重标权代价为零。局部搜索第一次以完整最小键出队一个这样的格子时，便已取得最优答案，无需再走完整个后缀。不能在首次发现某个 true 邻格时就返回：尚未出队的候选仍可能提供更短路径，或同长但首方向更早的路径。

**完整保留首步平手规则。** 普通 0/1 BFS 可以求对最短长度，但任意 predecessor 链不保证上、右、下、左的规范首步。这里把首次方向作为严格次级目标，令 `rank(U,R,D,L) = (0,1,2,3)`，搜索键为：

```text
K = 4*k + firstRank
```

只从 source 的开放首邻格初始化：对第 `rank` 个邻格 `n`，键为 `4*w'(source,n) + rank`。以后经过每条边只增加 `4*w'`，保留首次方向的低两位。不同 `k` 的键区间互不重叠，同一 `k` 内较早的方向严格更小，因此最小终端键同时给出最短长度和基线规范首步。返回 `neighbors[source][K & 3]`；本实现不把任意搜索父链缓存为完整规范路线。

队列使用 8 个循环桶。初始键在 `0..7` 内，后续边只增加 0 或 4，且每次只扩展当前最小键。因此同一时刻的待处理键不会跨越 8 个优先级，两个不同的待处理优先级不会混入同一个循环桶。记录保留完整键；出队时检查它是否仍是该格的最优键，丢弃陈旧项。桶内相同键的累计重标权代价和首方向均相同，可以任意顺序处理，不影响最小终端键。

**有界工作与复用。** 每次最多弹出 `max(32, min(256, N/16))` 条记录，其中 `N = W*H`，陈旧记录也计入预算。预算耗尽返回内部状态 `-2`，随即查询原精确距离场；只有整个队列真正耗尽才返回不可达 `-1`。这两个返回值不能混淆。

每个静态缓存条目还记录目标在当前地图版本的局部查询次数。在条目仍驻留时，同一目标、同一版本最多尝试 4 次；第 5 次直接建立或修复共享动态距离场。一次搜索超预算也立即转回精确场。地图版本改变会重置计数；静态条目被淘汰后，计数随条目一起丢弃。已有当前版本的精确场始终优先复用。这些阈值只是限制额外工作的策略，不决定答案，也不代表经过证明的最优性能分界。

**特殊起点和目标。** source 可以被动态封锁：搜索仍从它的开放首邻格播种，后续只能进入开放格。target 被封锁时，保留 `nextStep()` 的直接 `-1` 返回。静态势函数非有限的 source 不进入局部搜索；永久墙 source 的通用 API 行为继续交给原回退。`nextStep(source == target)` 仍按开放邻格选择首步，不把 source 自身作为零步终端；正常仿真在调用前已执行到达判断。该 API 行为与 `distance(source == target) == 0` 的语义不同，不能混同。

这层搜索复用已存在的静态距离和证书，不代替冷目标的完整静态 BFS；也不修改动态距离场的维护方式。局部工作不合适时，仍由下一层提供完整精确答案。

### 5. 动态精确距离与完整 BFS 回退

需要完整精确距离，或局部绕行未直接作答时，`distancesTo()` / `distancesFrom()` 使用按源缓存的完整动态距离表。每张表记录自己的版本，按需追上地图变化。

`repairDistances()` 在封路时先删除失去全部最短路前驱支持的影响区域，保留其原距离用于继续传播；这样断开的分量不会发生反复递增距离的循环。随后从仍有效的边界和新开放格重新播种，用 FIFO 松弛恢复精确标签。源点始终保留零距离，即使它被封锁。

版本差超过 256，或失效区域／松弛量超过 `max(32, N/8)` 时，立即改用完整 BFS。以上阈值不会返回近似答案。

完整动态 BFS 从 `dynamicInitial_` 复制当前图的初值，其中墙和封锁格暂记为 `-1`，开放格为 `kInf`。这样扩展邻格时只需检查它是否仍为未访问的 `kInf`。源点无条件置零；搜索结束后，墙和封锁格恢复为对外的 `kInf`，唯独源点仍保留零。多源充电桩 BFS 使用同一初值，只把当前开放的桩作为根，结果按地图版本复用。

## 封锁起点与引用寿命

基线允许从被封锁的起点离开，但不允许再次进入该格。这使该特殊情况不能简单按无向距离直接读表。`fromDistances()` 的顺序为：

1. 起终点相同，返回 0。
2. 目标不可行，返回不可达。
3. 起点可行，直接读取目标的反向距离表。
4. 起点被封，取可行邻格的最小距离加一。

最近充电桩查询也使用相同的首步修正，但封锁充电桩不会仅因和源同点而成为可选桩。

`distancesTo()` / `distancesFrom()` 返回的引用仅保证在下一次缓存查询或地图修改前有效。调用方取得表后立即完成读取，不能在持有引用期间嵌套其他可能淘汰该表的查询，也不能跨 tick 保存引用。

## 有界缓存与内存

- **动态距离表预算为 96 MiB：**包含动态 LRU 距离表及两张常驻 `int` 距离表（不可达表与动态最近桩表）。LRU 使用槽号双向链表，命中移动与淘汰映射更新为 O(1)。
- **静态距离与证书 payload 预算为 64 MiB：**每个目标、每格 2 字节距离加 1 字节 DAG 证书。容量为 `max(1, min(N, floor(64 MiB / (3*N))))`，不再额外限制为 512 个目标；按需创建表，淘汰时复用条目。目标到槽的映射避免查表扫描，淘汰候选在有界条目中选择。200×200 地图的容量为 559 个静态目标。
- 两项都是指定缓存数组的 payload 预算，不是整个进程的内存上限。缓存条目元数据、分配器开销、地图、邻居、变化日志、BFS 队列、修复 scratch、独立静态最近桩表、机器人路线及位置标记另计。
- 局部绕行增加一套所有查询共用的 `detourKey[N]` 与 `uint32_t detourSeen[N]`，空间为 `O(N)`；在当前 32 位 `int` 目标平台合计为 `8*N` 字节。查询 stamp 避免每次清空全图，stamp 回绕时才清标记表。8 个桶复用自己的记录容量；单次至多从 4 个首邻格播种并按出队预算扩展，每格只有 4 条边，因此桶工作空间受该固定预算约束。另有每静态条目的版本与尝试计数；不为每个目标各分配一套搜索 scratch。
- 变化日志最多对应 200,000 个输入事件。每机器人路线不重复顶点；全部路线位置标记至多 `300 × 40000 × 2` 字节。
- 不预分配 `N×N` 全源矩阵，也不为每个地图版本永久保留一组表。冷表追版本或被淘汰后重建；共享 scratch 在查询之间复用。

## 派单、占据、热点和输入输出

待分配订单使用有序集合，键为 `(-priority, arrival, numeric_id, internal_index)`。取消和分配时删除；死亡重排仍保留原 arrival。

订单的“取货点到送货点 + 送货点到最近可行桩 + 安全余量”只依赖地图，按地图版本缓存。初始缓存版本设为无效值，确保版本为零时也会第一次计算。仅当两个端点都可行时利用无向图交换查距方向；存在封锁端点时保留正向语义。

一次派单后保存剩余合格空闲机器人的 `(编号, 位置, 电量)` 快照。只有路网版本、待分配集合版本或这个快照变化时，才重新尝试此前失败的分配。第一轮派单不依赖当前 tick、占据或充电预订，因此这项跳过安全；新增订单老化、拥堵权重或预订成本时，必须重新检查缓存依赖。

活车占据表支持常数时间查询。移动先释放旧格再占新格，死亡释放，救援按编号逐个占格。多个死车可以停在同一格，但活车最多一辆。

找桩预订使用 tick 标记，先登记当前 CHARGING 和 TO_CHARGER，再按机器人编号加入新预订，避免每 tick 清空整个地图。

热点使用逐行区间差分：每辆活车的曼哈顿覆盖在各行形成区间，累加后按行扫描非墙格。复杂度为 `O(W×H + R×min(H, 2×radius+1))`，封锁地面仍参与热点候选。

输入按检查器保证的 ASCII 标准十进制格式解析，兼容 LF/CRLF；输入只加载一次。日志按产生顺序写入有限输出缓冲，达到阈值后刷新，不保存整场日志。延迟和、步数与等待计数使用 64 位整数。

## 必须保留的兼容行为

| 行为 | 兼容细节 |
|---|---|
| 接单 | 越界或墙格拒绝；封锁格仍可创建订单。拒绝订单不进入订单表 |
| 取消计数 | 订单只要存在，每次 CANCEL 都增加 cancelled，即使随后输出 CANCEL_FAIL；不存在或被拒订单不增加 |
| 派单顺序 | 优先级降序、原到达 tick 升序、数值订单号升序 |
| 派单平手 | 取货距离相同选择编号较大的机器人，保留基线 `<=` |
| 救援 | 停机至少 100 tick 且原格无活车；恢复电量为 `batteryMax / 2`，向下取整 |
| 充电结束 | 加电并封顶后，`battery * 10 >= batteryMax * 9` 即结束 |
| 距离 | 同点为零优先于目标封锁；其他情况目标必须开放，源可以被封 |
| 找桩 | 优先检查预订和电量余量；回退取最近可达开放桩，忽略预订和电量 |
| 找桩平手 | 桩按行优先枚举，严格 `<` 保留较早的桩 |
| 到达优先级 | 已在目标先于零电量和目标封锁处理；走掉最后一格电量后仍可立即到达 |
| 同点取送 | 取货后本 tick 不再次执行送货；两次到达分属不同 tick |
| 到桩 | 到达只进入 CHARGING，下一 tick 才增加电量 |
| 连续等待 | 只有占据冲突增加连续等待；封锁目标或断路只增加累计等待，不清空原连续等待 |
| 让路 | 已连续冲突等待至少 4，且理想下一格不是目标；选 U/R/D/L 中首个空的可行格，即使它离目标更远 |
| 移动顺序 | 编号升序，每次移动更新占据后再处理下一辆；死车不占格 |
| 热点 | 排除墙和死车的贡献，封锁地面仍是候选；平手选行优先最早格 |
| 平均延迟 | 使用 `(sum + delivered / 2) / delivered` |

## 修改入口与复查重点

- 派单资格、优先级、电量估计：改 `dispatch()`、`PendingKey`、订单 `remainingCost`，同时检查派单快照依赖。
- 充电和救援：改 `rescue()`、`charge()`、`seekChargers()`，保留预订形成顺序和下一 tick 才充电的时机。
- 路径规则：改 Grid；同步检查静态距离下界、DAG 证书、完整路线失效、局部绕行的重标权与首方向编码、封锁源和缓存引用寿命。若边权、邻接规则或方向顺序改变，必须重新证明 `w' ∈ {0,1}`、`4*k+firstRank` 与 8 桶的适用性。
- 移动：改 `move()`、`routeStep()`、`moveTo()`、`arrive()`、`die()`，同时维护占据、路线游标和待分配集合。
- 统计：改事件处理、`arrive()`、`die()`、`report()`、`finish()`；取消计数不等于成功取消数。

合法输入可能没有充电桩、没有事件、地图不连通，电池上限可以为 1，低电阈值可以为 0，热点半径可以为 400，事件坐标可以越界。规则修改后应继续与原始 baseline 对拍，尤其覆盖：同 tick 多次封路/开路、封锁源和封锁目标、所有桩封锁、组件断开再连通、同点取送、同距派单、救援与占据交错、连续等待后的 sidestep、不同订单状态的重复取消，以及 200×200 地图上超过缓存容量的根访问。

独立 Grid 对拍应先调用冷 `nextStep()` 再查询同目标距离，避免完整距离场提前建好而绕过局部搜索。已有 200×200、760 个根的 LRU 夹具覆盖新的 559 个静态目标容量及动态缓存容量，无需仅因移除 512 上限而额外扩大夹具。还应保留预算耗尽后的精确回退和同版本第 5 次查询物化场的覆盖。

更改尺寸、边框或事件上限时，应先复核 `uint16_t` 距离与路线位置、扁平邻居访问、队列暂存位和变化日志上界，再运行完整等价验证。
