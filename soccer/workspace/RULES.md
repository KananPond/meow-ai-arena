# 2v2 足球 · 比赛规则 v1

两队各 2 名球员，在一块四角切掉的封闭球场里踢 1200 步，进球多的队赢。没有界外、角球、越位、犯规：球撞墙就反弹，只有进球。

**每名球员由一个独立的程序控制**。你和队友各写一个程序（各控制一名球员）。两人可以互相读对方的代码（也可以照抄），但各交各的。比赛中两名队友每步可以互发 1 字节消息，消息含义完全由你们自己约定。

规则的唯一权威实现是 `soccer.hpp`（C++17 头文件，裁判就用它）。本文与它有出入时以它为准。

## 1. 场地与物体

坐标单位"毫"，整数。x 向右、y 向下，原点在左上角。

| 项目 | 数值 |
|---|---|
| 场地 | W × H = 12000 × 8000。四角各切掉一个直角边为 1000 的等腰直角三角形（45° 斜墙） |
| 球门 | 左右两侧墙正中各开一个宽 2000 的口：y ∈ [3000, 5000] |
| 球员 | 圆，半径 300 |
| 球 | 圆，半径 150 |

**你永远看到"自己向右进攻"的视角**：对方球门在右边（x = 12000），自己的球门在左边（x = 0）。你收到的坐标、速度和你输出的向量都是这个视角，裁判负责换算。所以不用管自己在场地哪一边。

## 2. 每步动作

每步你输出 5 个整数 `AX AY KX KY MSG`：

- **加速度 (AX, AY)**：加到你的速度上。长度超过 40 时按比例缩短到 40。
- **踢球 (KX, KY)**：(0, 0) 表示不踢。踢球**有效**要同时满足：
  1. 本步开始时，你的中心与球心的距离 ≤ 500；
  2. 你的踢球冷却为 0；
  3. 向量不为零。

  有效踢球的向量先缩短到长度 ≤ 800，**直接成为球的新速度**（替换原来的速度，与球原速、你的速度都无关）。同一步几个人都有效踢球：各自缩短后**相加**，再缩短到 ≤ 800。踢完冷却变为 5，**踢球这一步末尾不减**，之后每步末尾减 1：第 t 步有效踢球，第 t+1～t+5 步都不能踢（这 5 步你收到的 CD 依次是 5、4、3、2、1），第 t+6 步起可以再踢。无效的踢球什么也不发生，也不影响冷却。
- **消息 MSG**：0..255 的整数，下一步**只有队友**能看到（对手看不到）。超出范围按 0。

"缩短"（限长）的精确算法：若 x² + y² > m²，令 d = ⌊√(x² + y²)⌋，(x, y) ← (x·m / d, y·m / d)，除法向零取整。

## 3. 每步结算顺序

1. 收齐 4 人的输出，换算回场地坐标。
2. **踢球**（按第 2 节，用本步开始时的位置判断距离）。
3. **加速**：球员速度 += 限长后的加速度。
4. **移动**：球员和球的位置 += 各自速度。
5. **碰撞**（按以下次序）：
   1. **球员与球员**：两圆重叠就沿连心线各推开一半，并按恢复系数 0.5 交换法向速度（等质量）。所有球员对的修正都由碰撞前的同一状态算出再相加（同时结算，与编号无关）。
      两人圆心**完全重合**（连心线没有方向）时：按两人本步移动前的相对位置分开（各退回自己来的方向，即相对速度的反方向）；若移动前也重合（相对速度为 0）：不同队的两人沿 x 方向各自退向本方球门，同队的两人队内 0 号向上（y 减小）、1 号向下。这样分离方向与编号、场地左右都无关，换边后仍严格镜像。
   2. **球员与墙**：推回场内，朝墙的速度分量清零。球员不能进球门口（门口对球员来说是墙）。
   3. **球与球员**：球被推出到球员体外，朝球员的相对速度按恢复系数 0.5 反弹（球员不受影响）。同样是同时结算。
   4. **进球判定**：球心 y ∈ [3000, 5000] 且 x < 0（进左门，**对方**得分）或 x > 12000（进右门）。
   5. **球与墙**（没进球时）：推回场内，朝墙的速度分量按恢复系数 0.8 反弹。球心在门口 y 范围内时，左右两面墙对球不存在。
6. **摩擦**：球员速度 ×9/10，球速度 ×97/100（都向零取整）。冷却减 1（本步刚有效踢球的人不减）。
7. 步数 +1。若本步进球：进球方 +1 分，全体回开球站位，**失球方开球**。若没进球、但已经连续 300 步没有任何有效踢球：比分不变，全体回开球站位，由上一次开球的队再开球。

碰撞的精确整数公式见 `soccer.hpp` 的 `players_collide`、`wall_collide`、`ball_players`（各十几行）。

**由此推出的数**（整数逐步递推的实际值，不计碰撞）：球员从静止沿一个方向每步加速 40，第 1 步移动 40、第 5 步 163、第 10 步 258、第 20 步 347、第 30 步 379，之后趋于每步 **391**（取整后的极限，不是 400；此时保存的速度是 351）；累计移动：10 步 1644、20 步 4790、30 步 8463、**40 步 12318**（跑完场长 12000 要 40 步左右）。踢出的球第一步走 800，之后每步 ×0.97（向零取整），不撞墙的话一脚共滚约 2.46 万（124 步后停下，两个场长）。球的最高速度约是人的两倍。要精确预测就用 `soccer.hpp` 模拟，不要用这些约数。

## 4. 整数约定

全部是 64 位整数运算：除法向零取整（C/C++ 的 `a / b`），平方根向下取整，所有"乘一个系数"都写成 `v × 分子 / 分母`。没有浮点、没有随机（除了开球站位，见下）。**同样的局面和动作，结果逐位相同**，所以你可以用 `soccer.hpp` 在自己的程序里精确地预测球（`soccer::predict_ball`），或复制一个 `soccer::Game` 往前模拟。

## 5. 开球

- 球放在 (6000, 4000 + δb)。
- 开球方：1 号球员（队内 0 号）站在球的正后方 500 处（刚好够得着），2 号（队内 1 号）站在离本方底线 2000、y = 4000 + δ2 处。
- 非开球方：队内 0 号站在离中线 1500、y = 4000 + δ1 处；队内 1 号同上（离本方底线 2000、y = 4000 + δ2）。
- 两队站位左右镜像。δb、δ1、δ2 ∈ [−600, 600]，每次开球由比赛种子的 SplitMix64 依次生成（算法见 `soccer.hpp`）。这是整场比赛唯一的随机。
- 开球时所有速度、冷却清零。

## 6. 胜负、赛程

- 1200 步结束，进球多的队胜，相同为平局。
- 物理左右严格镜像。每个种子打两局：两队交换场地，第一次开球分别由两队各开一次。
- 每对队伍打几个种子、积分办法，由主办方另行公布。

## 7. 程序的输入输出

程序从标准输入读、向标准输出写，**每行输出后必须刷新**（`std::endl` 或 `fflush(stdout)`）。调试信息写到标准错误（`std::cerr`），**不要写到标准输出**。读到文件结束（EOF）就退出。

**开局**（7 行）：

```
SOCCER2V2 1
W H GOAL CHAMFER RP RB                              12000 8000 2000 1000 300 150
ACC_MAX PF_N PF_D BF_N BF_D                          40 9 10 97 100
KICK_MAX KICK_REACH KICK_COOLDOWN                    800 500 5
E_WALL_N E_WALL_D E_BALL_N E_BALL_D E_PP_N E_PP_D    4 5 1 2 1 2
STEPS STALL MSG_MAX                                  1200 300 255
IDX STEP_MS FIRST_MS                                 我是队内 0 号还是 1 号；每步 CPU 预算；开局 CPU 预算（毫秒）
```

（右边是说明，实际只有数字。）

**每步**（从第 0 步开始，6 行，全部是"自己向右进攻"视角的整数）：

```
T LEFT MY_SCORE OPP_SCORE MATE_MSG     步号、剩余步数、我方得分、对方得分、队友上一步发的消息（第 0 步为 0）
BX BY BVX BVY                          球的位置、速度
X Y VX VY CD                           自己（CD = 踢球冷却剩余步数）
X Y VX VY CD                           队友
X Y VX VY CD                           对手（队内 0 号）
X Y VX VY CD                           对手（队内 1 号）
```

**回复**一行：`AX AY KX KY MSG`。

### 完整示例

裁判发来（你是 B 队的队内 0 号，所以看到的是翻转后的视角）：

```
SOCCER2V2 1
12000 8000 2000 1000 300 150
40 9 10 97 100
800 500 5
4 5 1 2 1 2
1200 300 255
0 10 1000
0 1200 0 0 0
6000 4446 0 0
4500 4405 0 0 0
2000 3813 0 0 0
6500 4446 0 0 0
10000 3813 0 0 0
```

这是第 0 步：对方开球（对方 0 号站在球后 500 处，x = 6500 > 6000，在球的右侧，也就是对方半场）。你的回复，例如"向右上方加速、不踢球、给队友发 1"：

```

```

下一步裁判发来 `1 1199 0 0 ...` 和新的局面；你的队友在他的第 1 步输入的 MATE_MSG 位置看到 `1`。

## 8. 时间、出错

| 情况 | 处理 |
|---|---|
| 每步 CPU 预算 | **10 毫秒**（进程 CPU 时间）。从你上一步的回复被读到起，到本步的回复被读到止，你的进程用掉的全部 CPU 都算（回复之后接着偷偷算，算进下一步） |
| 第 0 步 | 预算 1000 毫秒，从程序启动算起（含读开局信息） |
| CPU 超预算 | 本步动作作废，按 `0 0 0 0 0` 执行（裁判照样等你这一步的回复）。累计超时 30 次：结束你的程序，之后每步都按 `0 0 0 0 0` |
| 一步 1 秒（墙上时间）还没有回复 | 结束你的程序，之后每步按 `0 0 0 0 0`（第 0 步是 5 秒）。以裁判读到你回复的时刻为准：截止之后才到的回复同样算失去响应 |
| 输出不合法 | 不是恰好 5 个十进制整数、某个数的绝对值超过 10⁹、或一行超过 1000 个字符：本步按 `0 0 0 0 0`。空行忽略 |
| 程序崩溃 / 退出 / 关闭标准输出 | 之后每步按 `0 0 0 0 0` |
| 输出过量 | 已输出但裁判还没取走的行超过 64 行（每步只该输出一行），或一局标准输出累计超过 8 MB：结束你的程序，之后每步按 `0 0 0 0 0` |
| 内存 | 每个程序 1024 MB（程序用到的全部内存），超出视为崩溃 |
| 标准错误 | 只用于你自己调试；裁判每局最多保存 1 MB，多的丢弃 |

单线程即可（多线程的 CPU 时间会累加）。不要依赖墙上时钟决定算多少，按 CPU 时间或固定计算量更稳。

**运行环境限制（沙箱）**：每个程序在独立的 Windows AppContainer 沙箱里运行，只能用标准输入输出和裁判交流：

- **不能创建子进程**（每个程序同时只能有 1 个进程；`system()`、`CreateProcess` 等都会失败）。
- **不能读写文件**：读不到裁判、对手、其他目录里的任何文件，也不能往磁盘写文件（工作目录只读）。需要的数据请写进源码。
- 没有网络，看不到也打不开其他进程，环境变量只有最基本的几项。
- 这些操作失败时只是函数返回错误，程序不会因此被判负；但别依赖它们。
- 选手包里的 `match.py` 用的是同一个 `arena.exe`，本地对战也在这个沙箱里跑，限制和正式比赛相同。

## 9. 提交与编译

- 每人提交**一个 C++ 源文件**。可以 `#include "soccer.hpp"`（裁判用的同一份）和标准库，不能有别的本地文件。
- 编译前有一道简单的源码检查（`build.py` 里的 `check_source`，正式编译用同一份），不通过就算编译失败：
  - 不能包含系统 / 进程类头文件：`windows.h`、`winsock2.h` 等以 `win` 开头的，`processthreadsapi.h` 等以 `api.h` 结尾的，`unistd.h`、`process.h`、`io.h`、`direct.h`、`fcntl.h`、`tlhelp32.h`、`sys/…` 等；
  - 除 `"soccer.hpp"` 外不能用引号包含，不能用绝对路径或 `..` 包含，`#include` 后面不能是宏；
  - 不能用内联汇编（`asm`、`__asm__`）和 `dllimport`。
  - 标准库全部可以用（包括 `<bits/stdc++.h>`、`<x86intrin.h>` / `<immintrin.h>` 等编译器自带的 SIMD 头文件、`<thread>`、`<chrono>`）。注释和字符串里出现这些字不算。
  - 这道检查只是提前提醒；真正的限制是上面第 8 节的运行沙箱。
- 编译命令（Windows，g++ / w64devkit）：`g++ -std=c++17 -O2 -static -Wl,--stack,67108864 player.cpp -o player.exe`（同目录放 `soccer.hpp`）。
- 选手包里的 `build.py` 用同样的命令编译；`match.py` 用正式裁判 `arena.exe` 打本地比赛；`replay.py` 和 `viewer.html` 看回放。用法见 README.md。

## 10. soccer.hpp 里有什么（都在 `namespace soccer` 里）

| 名字 | 作用 |
|---|---|
| `Config` | 全部规则参数（默认值即本规则） |
| `Game` | 一场比赛的完整状态：`bx by bvx bvy`、`px[4] py[4] pvx[4] pvy[4] cd[4]`、`score[2]`、`t` 等，`step(acts)` 走一步（场地坐标；0、1 号是 A 队，`acts[p]` 是 p 号自己视角的输出），`observe(p)` 得到 p 号看到的局面 |
| `predict_ball(cfg, bx, by, bvx, bvy, n, out)` | 不考虑球员时，球接下来 n 步的位置和速度（含撞墙、进球），与裁判逐位一致。在你的视角里直接用即可 |
| `tdiv`、`isqrt`、`clamp_len` | 第 4 节的整数工具 |
| `Obs`、`parse_action`、`protocol_step` | 协议的读写（裁判用；你也可以用） |

在你的视角里模拟：把收到的局面填进一个 `Game`（自己 = 0 号，队友 = 1 号，对手 = 2、3 号），因为你的视角就是"A 队向右攻"，物理完全相同。注意对手的输出在 `Game` 里要按 B 队视角给（x 方向取反）。
