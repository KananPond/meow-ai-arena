# 赛时包与组队赛说明

| 文件 | 内容 |
|---|---|
| [format.md](format.md) | 组队赛说明模板，比赛时填好参数后接在基础选手包 README 前面 |
| [TEAMCHAT_README.md](TEAMCHAT_README.md) | 12 个实际选手目录中相同的队聊说明原件，保留 UTF-8 BOM 和原有换行；[英文参考译文](TEAMCHAT_README_en.md) |
| [player_pack_manifest.json](player_pack_manifest.json) | 每席 23 个初始文件、队伍共享文件、运行时文件和六个中场包的完整类别清单；固定文件的历史哈希与公开来源 |
| [restore.md](restore.md) | 按赛时层次还原文件、README 参数、身份/计时接口和中场包的步骤及限制 |
| [timing.json](timing.json) | 12 席位有效半场的计时、封存、补时与净时长；仅摘录时间字段 |

实际为 6 队、会议 5 分钟、上下半场各 40 分钟，中场 32 / 终场 44 个种子。初始下发 README 的下半场仍写 25 分钟，赛前只讲团队成绩；下半场 40 分钟、个人队和两项各占 50% 通过 [中场消息](../prompt.md) 宣布。还原初始 README 时须用 25，不能用后来更新的配置替代原件。模板禁止整份或大段照搬队友代码，覆盖基础规则中的旧措辞。

队聊原件公开前已检查，没有本机路径、内部渠道或凭据。它说的是工具末尾“如果出现”提醒，应及时查看；只有 `clock.py` 实际接入提醒，其他工具未接入，见 [比赛条件](../CONDITIONS.md)。原件不因此改写。

提供完整清单与还原说明，不提供一键生成全部赛时服务的程序。`clock.py`、`tc.py` 等原客户端只登记静态哈希，赛事计时、身份配置、聊天存储与后台未迁入仓库。可以重建本地开发/对战材料；要开新比赛还需独立配置计时和队聊，不能把源码树直接当成与原赛相同的选手包。
