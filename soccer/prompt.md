# 发给选手的消息

开赛消息仅队友名不同，下面把该名字恢复为 `{队友}`；时间已填为实际的 5/40 分钟。中场消息是实际发送版本。逐人原始文件见 [prompts/](prompts/README.md)。这里是主办方提示词，不是选手会话、队聊记录或思考内容。

## 开赛：会议与上半场

```text
你和另一个 AI 模型（{队友}）组成一队，参加 2v2 简化足球编程对抗赛。你们各写一个 C++ 程序，各控制本队一名球员；对手是其他 AI 模型组成的队伍。最终只看全队的比赛成绩。

先读当前文件夹里的 README.md（赛制、时间安排、工具）、RULES.md（规则全文）和 TEAMCHAT_README.md（和队友沟通的工具 tc.py）。

规则要点：12000×8000 的封闭球场，一局 1200 步，进球多的队赢。每步你的程序读局面、输出一行 `AX AY KX KY MSG`（加速度、踢球向量、发给队友的一个 0..255 的数），每步 CPU 预算 10 毫秒。你看到的永远是“自己向右进攻”。队内 0 号 / 1 号每个种子轮换，程序从开局信息里的 IDX 得知。soccer.hpp 是裁判用的同一份引擎，可以 include 来精确预测；本地用 python match.py 和基准、中档陪练、陪练（也可以带上队友的程序）对打，python replay.py 或 viewer.html 看回放。

现在是战术会议（5 分钟）：只用 tc.py 和队友讨论打法、分工、两个程序怎么配合，不写代码，不写文件。会议结束时主办方会在聊天里发“可以开始写代码”；在那之前用 python tc.py wait 等消息，不要结束本轮。之后是上半场开发（40 分钟），python clock.py 显示当前阶段和剩余时间。

要点：
- 你的球员程序是你目录里的 submission/player.cpp，收卷时它是什么就交什么：不要让它长时间停在编译不过的状态；
- 各自的程序自己写：可以读队友的代码、参考思路、约定配合的协议，但不要整份或大段照搬队友的程序；队友的文件夹可以看，不要改；
- 只在当前文件夹内写文件（聊天工具除外）；禁止联网，禁止求助其他模型（包括启动子代理：subagent、Task / Agent 工具、后台并行代理之类），禁止查看其他队伍的资料；
- 这台机器上同时运行着其他程序：只能结束你自己启动的进程（按进程号），不要按名字批量结束进程；
- 不要向我提问，也不要等待我确认。

上半场到点时主办方收卷，并在聊天里通知；收到通知后停止修改，结束本轮。
```

## 中场：下半场与新增个人队

```text
上半场已经结束，中场赛打完了：所有队伍的上半场版本互相比赛。中场包在队伍目录 ..\halftime\ 里：RESULTS.md 是成绩和你们队的对局列表，replays\ 是你们队每一局的回放（含对基准、中档陪练、陪练的局），tools\ 是复盘工具 replay.py 和网页查看器 viewer.html（用法见你目录里的 README.md）。先用 python tc.py inbox 看队友的消息。

**下半场规则调整（请仔细读）**
下半场 40 分钟，python clock.py 看剩余时间。最终成绩改为两部分，各占 50%：
1. 团队分：和之前一样，你和队友各交 submission/player.cpp，组成你们队，和其他队伍单循环。
2. 个人分：你一个人再组成一支“个人队”：你的 submission/player.cpp，加上你另写的 submission/partner.cpp（控制个人队里的另一名球员），和所有其他选手的个人队单循环。不交 partner.cpp，就用 player.cpp 打两个位置。

每局胜 3 分、平 1 分、负 0 分，两部分都按得分率计算。
个人队的两份程序都必须是你自己写的：可以参考队友的思路，但不要整份或大段照搬队友的代码。团队这部分仍然可以读队友的代码、约定配合协议。
其他不变：只改你自己目录里的文件，队友的文件夹可以看、不要改；不要向我提问。下半场的 player.cpp 编译不过时，用你上半场的版本上场；partner.cpp 编译不过时，用 player.cpp 打两个位置。到点主办方收卷并在聊天里通知，收到后停止修改，结束本轮。
```

## 赛后复盘问题

下面的 `{成绩段}` 等变量由最终两张榜填入；每人的最终消息在 [消息索引](prompts/README.md)。

```text
比赛全部结束了，成绩已经出来。

团队赛：{成绩段}
个人赛：{个人段}

请做一个简短复盘，总共不超过 300 字：
1. 你们队做得最对的一个决定；
2. 你们队最大的失误，以及原因；
3. 你和队友的分工、配合实际是怎样进行的；
4. 评价你的队友（{队友}）：他做得好的地方、不足的地方，各一句；
5. 下半场你在团队程序和个人队程序之间是怎么分配时间的，为什么；
6. 如果重来一次，你会在战术会议上提出什么不同的方案。

不要修改任何文件，也不要再运行代码或聊天工具，直接用文字回答。

团队赛积分表：
{成绩表}

个人赛积分表：
{个人榜}
```

程序实际收卷以主办方封存为准。本仓库不提供消息里引用的实时队聊、计时及启动服务，不能只复制消息就声称复现了全部比赛条件。
