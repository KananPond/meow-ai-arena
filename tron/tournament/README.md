# 终场的赛事脚本（存档备查）

| 文件 | 内容 |
|---|---|
| `tourney.py` | 终场的赛程、统一编译、绑核跑对局、并入旧对局、计分、成绩表、回放、局内统计。和比赛时逐字节相同 |
| `bt.py` | Bradley–Terry 拟合和自助法区间（`tourney.py` 调用）。和比赛时逐字节相同 |
| `hostlib.py` | 赛事脚本共用的部分：读配置、路径、日志、消息模板（`tourney.py` 依赖它）。和比赛时逐字节相同 |
| `赛程_1018终场.json`、`赛程_1020补打.json` | 10-18 终场和 10-20 补打的赛程表：每局的局型、地图种子、座位、所在的榜和自助法分块，以及冻结时的赛程指纹 `digest`。主办方电脑上的路径换成了 `<…>` 占位，其余没有改。`RESULTS_*.md` 里写的"地图种子在 `赛程.json`（不公开）"是赛时的说法，开源时决定公开 |
| `final.json` | 10-20 补打并重算时的赛事配置：两张榜的名单、锚点、权重、赛程参数、并入哪些旧对局。主办方电脑上的路径换成了 `<…>` 占位，编译器路径去掉了，其余没有改 |

计分的入口是 `tourney.py` 里的 `score()`（每个局型一个 BT 实力值，锚点豆包 = 0，按 50/30/20 加权，分层整块自助法 1000 次）和 `rank_score()`（旧计分：名次分，只作参考）。两两比较怎么取、greedy 和补位副本为什么不计分、并入的对局怎么筛，见 `../results/RESULTS_正式榜.md` 的开头和第 7 节。

**这几份文件不能单独复现终场**：

- `tourney.py` 没有命令行入口，比赛时由主办方的总控脚本调用；总控脚本还负责开赛、计时、封存、补时、生成消息，没有放进仓库。
- 终场并入了 10-18 终场和两次快速预览的对局（逐局结果在 `../results/预览并入.jsonl.gz`），重算需要按配置里的 `imports` 把它们放回原来的目录结构。
- 赛程表在本目录（`赛程_*.json`），各局的地图种子、座位也都在逐局结果里，可以按它们重打任何一局（见 `../results/README.md`）。

想自己办一场同样规则的比赛，最简单的办法是用选手包里的 `arena.py`（`run_games` 直接调用裁判）排对局，参考 `../challenge.py` 的写法，再用 `bt.py` 拟合。
