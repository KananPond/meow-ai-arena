# 成绩和逐局结果

全部由终场的赛事脚本（`../tournament/tourney.py`）生成，是 10-20 补打 Mercury 后重算的版本。名字用短名，对应的模型见 `../bots/README.md`。成绩表、统计表和 JSON 里主办方电脑上的绝对路径已经换成仓库里的相对路径或 `<…>` 占位，其余内容和原件相同。

| 文件 | 内容 |
|---|---|
| `RESULTS_正式榜.md` | **正式榜**（10 位正式选手）：总分、区间、名次区间、两两之差、相邻名次、三个局型的实力值、1v1 对强档陪练、编译和超时、用时、赛程和对局来源、旧计分（名次分）附表 |
| `RESULTS_强对手榜.md` | **强对手榜**（再加 2 位参考选手和强档陪练线），结构同上，另有"和陪练线比"一节 |
| `视频统计_正式榜.md`、`视频统计_强对手榜.md`（及 `.json`） | 局内统计：每人在每个局型里的独占第一、存活回合、撞死别人、抢格胜负、死因分布。只统计正式模式的局，不含并入的快速预览对局，所以和总分不是同一批局 |
| `results.json` | 两张榜的全部计分结果（机器可读）：`boards.<榜名>.score` 里有每人的总分、分项、区间、两两之差和名次区间 |
| `results.jsonl.gz` | 10-20 补打的 1446 局，每行一局（带逐回合走法 `moves`） |
| `预览并入.jsonl.gz` | 并入计分的其他对局：10-18 终场 4267 局（`source` = `final1018`）和两次快速预览（`preview1`、`preview2`，快速模式）。每行一局 |
| `清单.json` | 终场开赛时冻结的东西：引擎和裁判各文件的哈希、编译器版本和参数、每个程序的源码哈希 |
| `程序.json` | 每个上场程序的来源、源码哈希、编译结果哈希 |

每局的字段：局号 `gid`、局型 `type`（`1v1`、`3p`、`4p`、`12p`）、人数 `n`、地图种子 `seed`、各座位上的程序 `seats`（0 号座位在前）、名次 `rank`（0 起，同一回合死的并列）、名次分 `score`、回合数 `turns`、死在第几回合 `death_turn`（−1 = 活到最后）、死因 `cause`（`alive` 活到最后、`out` 出界、`obstacle` 撞障碍、`self` 撞自己的轨迹、`trail` 撞别人的轨迹、`headon` 抢格失败）、CPU 用量 `first_ms` `avg_ms` `max_ms`、超时回合数 `timeouts`、不合法输出 `invalid`、崩溃的回合 `crash_turn`、所在的榜 `board`、自助法分块 `block`、来源 `source`。

想重看某一局：在 `../workspace/` 里用 `python arena.py play 程序A 程序B … --seed 地图种子`，按 `seats` 的顺序列程序，列几个就是几人局（`greedy`、`sparring_hard` 直接写名字，`greedy_fill` 也写 `greedy`）。不看时间的 bot 打出的局和原来逐回合相同；按 `budget_left()` 决定搜到哪里停的 bot，过程会随机器状态略有不同。

注意：

- 快速预览的局是赛前（10-17）为了看个大概打的，快速模式只统计超时、不判罚，所以有超时的预览局整局丢掉了；它们的 `3p` 局不计分（终场不打 3 人局）。
- 两张榜的 1v1 共用同一批对局，多人局各打各的。同一位选手在两张榜上的分数不能互相比较。
- 成绩表里写的"地图种子在 `赛程.json`（不公开）"是赛时的说法；两次终场的赛程表已经公开，在 `../tournament/赛程_1018终场.json`、`../tournament/赛程_1020补打.json`。
