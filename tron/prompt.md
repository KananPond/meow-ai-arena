# 发给选手的消息

所有选手（10 位正式选手和 2 位参考选手）收到的都是下面的原文，逐字相同，不附加任何别的话。

## 开赛提示词

新会话，工作目录是只放了 `workspace.zip` 的空文件夹。只粘贴下面这段：

```text
按照要求编写尽可能强的光轮对战（Tron）bot。你的对手是其他顶尖 AI 模型写的 bot，它们可能主动设计战术。基准 greedy 是一个简单的 bot，它在正式比赛中是 0 分线；战胜基准不代表足够强，正式对手远强于基准。正式赛有 1 对 1、3～4 人、12 人三种局型，计分方法见 RULES.md。

解压 workspace.zip，阅读 README.md 和 RULES.md，然后开始。

要点：
- 时间从解压时开始算：推荐 45 分钟内完成，最长 60 分钟强制收卷。最终只看 bot 的强度；
- 只交 workspace/submission/bot.cpp 一个文件，到点时它是什么就交什么：不要让它长时间停在编译不过的状态；
- 只在当前文件夹内读写文件；允许使用本地工具、对战和复盘；禁止联网，禁止求助其他模型（包括启动子代理：subagent、Task / Agent 工具、后台并行代理之类），禁止查看其他选手的资料；
- 这台机器上同时运行着其他程序：只能结束你自己启动的进程（按进程号），不要按名字批量结束进程；
- 不要向我提问，也不要等待我确认。

完成后，用几句话简述你的策略。
```

提示词里说"greedy 在正式比赛中是 0 分线"，这是赛前的计分口径；比赛结束后锚点改成了豆包，greedy 只补座位、不计分（见 `README.md` 的"赛制"）。

## 续跑消息

只在非选手原因的中断（断网、服务卡死、额度用尽）后使用：主办方先按记录补好时钟，再在原会话里发这一条。`{原因}` 是下面实际用过的几种之一。

```text
{原因}，这不算你的问题。主办方已补回中断的时间，请从中断处继续。
```

| 选手 | 补时并生成消息的时刻 | `{原因}` |
|---|---|---|
| 盘古 | 10-17 00:55:30 | 刚才网络中断了 |
| dots | 10-17 00:55:30、01:28:01 | 刚才网络中断了 |
| 豆包 | 10-17 01:38:30 | 刚才 API 额度用尽导致中断 |
| Mercury | 10-20 04:06:34（+1200 秒）、04:08:49（−390 秒，更正补时量） | 刚才服务器过载，连接中断了（事后查明这次不是外部中断，见 `CONDITIONS.md`） |

## 没有发的消息

- **赛前狠话**：本期没有收集。
- **赛后复盘**：主办方准备了复盘消息（在原会话里请选手回顾成绩），最后决定不发，所以本期没有选手的复盘回应。
