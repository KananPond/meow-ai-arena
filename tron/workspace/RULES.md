# 光轮对战 · 规则

**一句话**：N 个人在方格棋盘上同时移动，走过的格子永久变成墙，撞上就死，活得越久名次越好。你写一个函数，每回合返回一个方向。规则的精确实现是 `tron.hpp` 的 `step`，与本文不一致时以它为准。

## 1. 局型与地图

| 人数 | 棋盘 | 地图 |
|---|---|---|
| 2（1v1） | 21×21 | 点对称（绕中心转 180°），两个出生点互为对称 |
| 3 | 25×25 | 就是 4 人局的地图，空出 3 号出生点 |
| 4 | 25×25 | 90° 旋转对称，4 个出生点互为旋转 |
| 12（全员乱斗） | 41×41 | 障碍 90° 旋转对称；出生点等距排在一个圆上（近似对称） |

- 坐标 `(x, y)`：x 是列、向右增大，y 是行、向下增大，都从 0 开始。棋盘存在 `s.cell[y][x]`。
- 障碍约占 8%，是 1～3 格的短条。出生点的上下左右没有障碍（12 人局是周围 3×3）。所有空地都与出生点连通。
- 地图只由人数和种子决定，生成器公开（`tron.hpp` 第 5 节）。正式比赛用你没见过的种子。
- 编号 0..N−1 就是座位号。**同一个 bot 要打所有人数**，开局看 `s.N`。

## 2. 每回合怎么结算

所有活着的人**同时**给出一个方向：`U` 上（y−1）、`R` 右（x+1）、`D` 下（y+1）、`L` 左（x−1）。

1. 出生点和走过的每一格都是这个人的**轨迹**，永久是墙。每个人当前所在的格（头部）也是轨迹。
2. 按本回合开始时的棋盘判断，目标格是下面任何一种就**死**：出界；障碍；任何人的轨迹（包括别人现在的头部、自己来的那一格——所以**掉头必死**）。
3. **抢格**：几个人走进同一个空格时，**优先级最高的占下这一格，其余的死**。
   优先级 = (编号 − 回合号) mod N，数值越小越优先（`tron::priority(s, k)` 直接给出）。
   - 2 人：偶数回合 0 号优先，奇数回合 1 号优先。例：第 6 回合 0 号、1 号都走进 (5,5)，0 号占下、1 号死；第 7 回合同样情形，1 号占下。
   - 4 人第 5 回合：1 号最优先，然后 2 号、3 号、0 号。
4. **互换位置**（A 走进 B 的格、B 走进 A 的格）：目标格是对方的头部，按第 2 条两人都死。紧跟在别人身后走进他刚离开的格：那一格已经是轨迹，死。
5. 没死的人走到目标格。死者停在原地，轨迹保留，仍然是墙。
6. 回合号加一。活着的不超过 1 人时对局结束（回合上限 W×H，实际到不了）。

## 3. 名次与计分

- **名次**：活到最后的第一；其余按死亡的回合，死得越晚越靠前；**同一回合死的并列**。
- **名次分** = (N − 名次) / (N − 1)：第一 1 分，末位 0 分。并列的人取所占名次的平均。
  例：4 人局，第 2、3 名在同一回合死，两人都得 (2/3 + 1/3) / 2 = 0.5。2 人局同时死，各 0.5。
- **总分**：所有选手和 **greedy 基准**（`bots/greedy.cpp`）一起打很多局，座位轮换。每局把同桌的人**两两比较**：名次靠前的算赢，同一回合死的算平。分三种局型——1v1、3～4 人、12 人——各自用这些两两胜负拟合一个 **Bradley–Terry 实力值**（和 Elo 同一把尺：差 400 分 ≈ 胜负比 10:1），**greedy 定为 0**，再按 **1v1 占 50%、3～4 人 30%、12 人 20%** 加权。**greedy 恰好是 0 分**，比它强为正，比它弱为负。名次附带 95% 区间（例如“第 2～4 名”）。
- `arena.py run` 在本地用名次分估分：你的平均名次分减去 greedy 替身的平均名次分，×100，同样按 50/30/20 加权。它和正式计分不是同一把尺（对手也不同），只用来比较自己的不同版本：本地分数高的版本，正式分数通常也高。选手包里的陪练 `sparring`（中等）、`sparring_hard`（强）只供本地测试，不参与计分。

## 4. 你的程序

```cpp
#include "tron.hpp"
int decide(const tron::State& s);   // 每回合调用一次，返回 tron::U / R / D / L（即 0 / 1 / 2 / 3）
```

- 只交 `submission/bot.cpp` 一个文件，只能依赖 `tron.hpp` 和标准库。主循环（读输入、写输出）由 `tron_main.cpp` 负责，你不用写。
- 全局变量、静态变量跨回合保留；每局开始时都是初始值。
- 调试信息写到标准错误（`fprintf(stderr, ...)`）。写到标准输出的内容也会被并进调试输出，不会干扰对局。
- **思考预算**：第 0 回合 2000 CPU 毫秒（含程序启动），之后每回合 **50 CPU 毫秒**。"CPU 毫秒"是你的程序自己消耗的 CPU 时间，等待、被挂起不算。`tron::budget_left()` 返回本回合还剩多少，留 3～5 毫秒余量。可以开线程，但裁判按整个进程合计。另有墙上时钟保险：2 秒（第 0 回合 4 秒）没有回复。
- **出错的处理**：返回值不是 0～3、超出预算、超过墙上保险时间——这一回合**沿上一回合的方向走**（第 0 回合按 `U`），你算出来的方向作废。程序崩溃或退出后，之后每一回合都沿上一回合的方向走（通常很快撞死）。
- 想往前推演：把 `State` 拷一份，自己填好每个人的方向，调用 `tron::step`。

## 5. `tron::State` 速查

| 字段 / 函数 | 含义 |
|---|---|
| `W`、`H`、`N` | 棋盘宽、高，本局人数 |
| `me`、`turn` | 你的编号；当前回合号（从 0 开始，就是你正在决定的这一回合） |
| `cell[y][x]` | `tron::EMPTY` 空地、`tron::WALL` 障碍、`0..N-1` 该玩家的轨迹 |
| `x[k]`、`y[k]`、`alive[k]` | 第 k 人头部位置、是否活着（死者停在死前的格子） |
| `last_dir[k]` | 第 k 人上一回合实际走的方向（第 0 回合之前为 `U`） |
| `death_turn[k]`、`cause[k]` | 死在第几回合（活着为 −1）、死因 |
| `DX[d]`、`DY[d]`、`opposite(d)` | 方向 d 的位移、反方向 |
| `inside(s,x,y)`、`is_free(s,x,y)` | 在棋盘内；在棋盘内且是空地 |
| `can_move(s,k,d)` | 第 k 人往 d 走一步，目标格现在是否空地（不考虑别人同时走进来） |
| `priority(s,k)`、`step(s,moves)` | 本回合的抢格优先级（小者优先）；精确结算一回合 |
| `budget_left()` | 本回合剩余的 CPU 毫秒 |
