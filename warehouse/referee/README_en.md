# Reproducing the official evaluation

These are the competition's referee programs, references, and hidden workloads. Except for two open-source fixes in `评测.py` (resume-version checks and memory checks on precise-timing repetitions) and removal of one local folder name from `进度.py`, the released scripts are byte-identical to those used during competition. Historical results are unchanged. Scripts expect the original Chinese directory structure: use `还原目录.py` to copy repository materials into that structure, then run there.

## Requirements

- Python 3. Competition and pre-release checks used Python 3.12 on Windows 11, with no third-party packages.
- g++ supporting `-std=c++20`. The competition machine used w64devkit GCC 16.2.0. Scripts call `g++` directly, or use `CXX` (PowerShell: `$env:CXX = "C:\path\to\w64devkit\bin\g++.exe"`, replacing it with the actual absolute path). Merely putting a compiler in repository `tools/` does not make these scripts discover it.
- bash for `.sh` scripts (Git Bash on Windows). Evaluation and scoring alone do not require them.
- Timing uses process CPU time. `workspace/tools/measure.py` includes non-Windows branches, but the complete workflow was validated only on Windows.
- System-path/compiler issue: after the competition machine's system code page changed to UTF-8, w64devkit's linker could not open paths containing Chinese characters (see [conditions](../CONDITIONS_en.md)). Restored directories contain Chinese names; `cannot open output file … Invalid argument` indicates that issue.

## Steps

```bash
python referee/还原目录.py ~/warehouse-rerun  # Run from warehouse/; target must be absent or empty, outside the repository
cd ~/warehouse-rerun
```

The restored folder includes all competition results. **To verify scoring only**, recompute without compilation:

```bash
python 裁判/盲评汇总.py       # Rewrites 赛事/盲评/汇总.md and 汇总.json
python 裁判/团队计分.py       # Rewrites 赛事/结果/团队成绩.md and 团队成绩.json
python 裁判/第1轮速度表.py    # Rewrites 赛事/结果/第1轮_速度成绩.md
python 裁判/成绩汇总.py       # Rewrites 赛事/结果/最终成绩.md
```

Pre-release checks confirmed these four outputs match `../results/` byte for byte.

**To rerun evaluation**, compile on an idle machine and do not run other evaluation tasks concurrently. Use a fresh `--out` or remove old results in the restored copy. `评测.py` now verifies fingerprints of source, workloads, baseline manifests, evaluation tools, and arguments. Completed entries are skipped only with matching fingerprints; missing/mismatched fingerprints cause an exit rather than silent reuse of historical results.

```bash
rm 赛事/结果/results1.jsonl 赛事/结果/results2.jsonl 赛事/结果/主程基准.jsonl
python 裁判/评测.py --phase 1 --entries 赛事/主程提交 --out 赛事/结果/results1.jsonl
python 裁判/评测.py --phase 2 --entries 赛事/接手提交 --out 赛事/结果/results2.jsonl --min-total 2
python 裁判/主程基准.py --min-total 2 --skip 队E  # Original lead code on old-format phase 2 workloads, for added value
python 裁判/修复判定.py  # Did final submissions repair their team's regression cases?
python 裁判/团队计分.py
python 裁判/成绩汇总.py
```

- Speedups divide competition-machine baseline times in `manifest.json` by your measured times. Correct outputs can be reproduced on another machine, but **speedups and scores are not directly comparable**. To remeasure baselines, run `python 裁判/准备隐藏负载.py --phase 2 --repeat 1` (about 17 minutes for all 9 reference workloads), and `--phase 1 --repeat 1` (the baseline is slow). Phase 1 now also generates 3 `hid_heavy_*` workloads: these were added for rematch phase 2 and were not used in Round 1.
- `gen.py` and `gen2.py` with seed 20261006 regenerate the included `.in` files byte for byte, verified before release.
- `--min-total 2` enables precise timing: repeat until 2 accumulated CPU seconds, up to 80 runs, then average. Without it, timing follows the initial measurements.
- Pre-release phase 2 and repair checks in the restored tree reproduced all 9 correct results for five finals, abnormal exits for Team E on every workload, and the same repair results as `../results/修复.json`.

**Other verdicts:**

```bash
python 裁判/击穿判定.py       # Rejudge 28 Round 2 cases; rewrites 赛事/击穿结果/矩阵.*; timeout cases take 1–2 minutes each
python 裁判/终版复测判定.py   # Post-contest final retest
python 裁判/终版体检_性能.py  # Performance probes
python 裁判/可行性验证/边界对拍.py 标准程序 被测程序 1500 --p2  # Random differential tests; usage at script start
```

The Round 2 and final-retest scripts internally run 3 cases concurrently and use wall time for timeouts. “Do not run concurrently” means do not launch other evaluation jobs alongside them. Contention and machine speed may affect timeout verdicts; no new serial checks of borderline cases have been recorded. Historical edge differential tests include illegal inputs; see the [audit supplement](../CONDITIONS_en.md). Defect classification (`赛事/击穿结果/缺陷点归类.json`) is manual and is not generated by scripts.

## Hardcoded local paths

- Competition root `C:arena5`: `ARENA` in `赛事工具.py`, and `/c/arena5` in `终版复测计时.sh`. Workspace creation, timing, sealing, and post-contest review packaging (`生成赛后评审包.py` writes there) use it. Evaluation/scoring alone do not.
- `巡检.py` and `进度.py` read Claude Code/Codex session records under the user profile and raw `赛事/运行记录/` outputs, which are not included.
- Builds default to `裁判/build/`. Security software on the competition machine blocked new executables elsewhere, explaining related script comments; other machines need not account for that.
- `A02_EVENT` redirects the event directory, as used for rehearsals.

## Differences from the competition setup

- Open-source `评测.py` fixes save a `fingerprint` for every new result and validate source, workloads, manifests, evaluation script, timing tools, and arguments on resume; old results without fingerprints cannot resume. Precise repetitions now enforce the 1 GB memory cap and record their peak `peak_mem_mb`. These fixes do not change scoring formulas or rewrite historical results. One local task-authoring folder name was removed from `进度.py`'s scope checks, leaving the internal-ID match. Other competition scripts are unchanged. This README and `还原目录.py` were added for release.
- `开跑.py` (CLI launches), `查用量.py` (quota checks), and `隔离测试.py` (tool working-directory checks) are omitted because they contain local installations, key-file locations, and account-pool model names. Consequently, `收卷.py` fails at its top-level import of `开跑`; Round 1 `开局.py <队> 准备` and `复盘.py --run` also fail importing it. Evaluation, verdicts, scoring, and package assembly are unaffected. Tool launch arguments are in [conditions](../CONDITIONS_en.md).
- `复盘.py` also needs omitted Round 1 metadata under `赛事/运行记录/`, so it cannot simply be rerun. Generated prompt templates are translated in [prompt_en.md](../prompt_en.md).
- Five internal scripts are omitted: `赛后流水线.sh`, `夜间评测.sh`, `夜间审计.sh`, and `夜间彩排.py` chained evaluation/rehearsal steps and depended on precompiled `裁判/build/` programs/timing logs; they do not run independently. `计分_个人赛版.py` belongs to an earlier individual format and was unused here. No other script calls them; run the steps above individually. Mentions of `赛后流水线.sh` and `.log` in `成绩汇总.py` and results refer to that batch and its log, included under `../results/final-check/`.
- `提示词/` contains only the 4 templates read by scripts: pre-match boast and the three rounds.
- Compiled artifacts and old hidden-workload manifest backups are omitted.
- `还原目录.py` copies upheld cases using `矩阵.json` into `赛事/击穿结果/被击穿用例/`. During competition `击穿判定.py` generated this folder; contents are identical.
