# 交接文档（src/）

## 文件结构
| 文件 | 内容 |
|---|---|
| `common.h` | 枚举、`Grid`（地图 + BFS 缓存）声明、`runAll` 入口 |
| `grid.cpp` | 地图、封锁集合、**带缓存的 BFS 距离表** |
| `sim.cpp` | 读入、逐 tick 流程（事件→救援→充电→派单→低电量充电→移动→报表）、收尾统计 |
| `main.cpp` | 读全部 stdin → `runAll` → 一次性写 stdout |

旧的 `util.cpp` / `old_stuff.cpp`（旧派单、`FLAG_FAST_BFS` 缓存版 BFS、`dumpCacheStat`）已删除，
没有任何东西依赖它们。旧缓存版 BFS 对不上输出的原因：BLOCK/UNBLOCK 之后缓存不失效。

## 优化思路
1. **BFS 距离表缓存**（`Grid::bfs`）：按“起点 + 封锁版本号”缓存；`G.version` 在封锁集合**真正变化**时 +1，
   旧表自动失效。环形缓存，约 300MB 上限。基线每次 `DIST` 都整图重跑 BFS（派单时 订单×机器人×3 次）。
2. **派单**：订单的 b（取货→送货）、c（送货点→最近可用充电桩）与机器人无关，随订单缓存（按封锁版本）；
   b/c 为 INF 的订单直接跳过。机器人→取货点的距离 a 用“取货点出发的 BFS 表”推算
   （见 `distToPickup`，处理了机器人站在被封锁格上时 `dist(a,b)≠dist(b,a)` 的情况）。
   候选机器人为空时提前结束。待派订单放在 `std::set`，遍历顺序即派单顺序，取消/重排队不再 O(n)。
3. **占据查询**：`occ[]` 格子→机器人，`OCC` 从 O(R) 变 O(1)。
4. **低电量去充电**：用缓存的 BFS 表 + 一次性构造的“被占用充电桩”数组。
5. **报表热点**：机器人少时直接数；机器人多时转到 (x+y, x−y) 坐标，曼哈顿球变正方形，用二维前缀和；
   机器人位置/存活没变化时复用上次结果（`posVersion`）。
6. 事件按 tick 分桶、一次解析；字符串状态改枚举；订单用结构体；输出写入一个大缓冲，一次 `fwrite`。

## 基线怪癖（SPEC.md 已过时，代码按基线实现，改动前务必留意）
- **派单平局**：a 相同选**编号大**的机器人（`a <= best`），SPEC 写的是编号小。
- **救援**只恢复 `batteryMax/2` 电量，不是充满。
- **充电**达到 `batteryMax*0.9`（`RB*10 >= max*9`）就变 IDLE 并输出 `CHARGED`，不是充满。
- **cancelled 计数**：只要订单号存在（含已完成/已取消/已取货），每次 CANCEL 都 +1，哪怕输出 `CANCEL_FAIL`；
  订单不存在的 CANCEL 不计。被 REJECT 的订单不存在，所以也不计。
- **LATENCY avg** 是四舍五入 `(sum + n/2)/n`，不是向下取整。
- 计数是靠解析日志行得来的（DELIVER/LOST/REJECT），这里改成直接计数，结果相同。
- `dist(a,b)` 起点不可通行时也能出发（机器人站在后来被封的格子上），方向敏感。
- 低电量选桩的第二步（全被占用）会选最近的、**可达**的桩；`d+safetyMargin>电量` 的只在第一步排除。
- 移动：到达目标检查在“电量为 0 → 停机”之前，所以 0 电量机器人在目标格上仍可完成 PICK/DELIVER/CHARGE。
- 让路（SIDESTEP）后立即做一次“是否到达目标”的检查。
- 事件解析与基线一致：整行 `getline`、tick 不在 [0,T) 的事件不会被处理、未知事件类型忽略。

## 风险 / 改需求时的注意
- 想改派单（比如加老化、搬运成本）：改 `dispatch()`；订单缓存的 `b/c` 只依赖地图与封锁，
  若新规则让 b/c 依赖别的状态，要把它们放进缓存失效条件。
- 想改充电/救援规则：`charge()`、`rescue()`、`lowBattery()` 各自独立，位置/存活变化要同步 `occ` 与 `posVersion`。
- `Grid::bfs` 返回的指针只在随后少量 `bfs()` 调用内有效（环形缓存，至少 16 槽）；不要长期持有。
- 封锁/解封必须走 `Grid::setBlock/clearBlock`，否则缓存不会失效。
- 同一格至多一个非停机机器人（`occ` 依赖这一点，由初始位置互异 + 移动前检查占据保证）。
- 订单号按 `int` 处理（合法输入 ≤ 1e9）。
- 本地用随机小图与基线对拍（含图外坐标、极低电量、频繁封路）验证过输出逐字节一致。
